# T0 Golden Reference — 精度说明更新

## 任务

将 `time.clock` 模块中所有关于精度的描述从微秒（microseconds / 微秒）改为纳秒（nanoseconds / 纳秒）。

## 需要改动的位置（共 5 处）

| # | 所在节 | 原文 | 改后 |
|---|---|---|---|
| 1 | `spec.interface` Timestamp 注释（仅条件 C 可见） | `内部精度：微秒` | `内部精度：纳秒` |
| 2 | `spec.interface` Duration 注释（仅条件 C 可见） | `内部精度：微秒` | `内部精度：纳秒` |
| 3 | Timestamp struct doc | `internal precision: microseconds` | `internal precision: nanoseconds` |
| 4 | Duration struct doc | `internal precision: microseconds` | `internal precision: nanoseconds` |
| 5 | `now()` Notes | `wrapping the microseconds since the Unix epoch` | `wrapping the nanoseconds since the Unix epoch` |

**注意**：位置 1 和 2 只存在于 `.nico` 源文件的 `spec.interface` 节，不出现在 `.rs` 文件中。
条件 A 只能看到 `.rs` 文件，因此**结构上只能触及 3 处**（位置 3、4、5）。
条件 C 提供 `.nico` 源文件，因此可触及全部 5 处。

## 评分 Rubric

### task_success（主要指标）
- **1.0**：正确修改了该条件可触及的所有位置（条件 A：3/3；条件 C：5/5）
- **0.5**：部分正确（漏改或错改）
- **0.0**：未完成或全部错误

### compile_rate
- 条件 A：将修改后的 `.rs` 内容替换原文件后，`cargo build` 通过 → 1；否则 → 0
- 条件 C：将修改后的 `.nico` 文件替换原文件后，`nicolas build` → `cargo build` 通过 → 1；否则 → 0

### 注意事项
- 仅改文档注释不改代码逻辑，compile_rate 应为 1，否则说明 LLM 误改了签名或实现
- 条件 A 的 LLM 可能会提示「.nico 中还有 2 处未改」，此行为记录但不影响评分（评分只看执行范围内的完成度）

## 预期实验结论

条件 A 最高得 0.5（受格式决定的可触及范围限制），条件 C 最高得 1.0。
若条件 A 得 1.0，说明 LLM 凭空创作了 .nico 内容（hallucination），需标记为无效 run。
