# E3 Golden Reference — cache.kv TTL 策略重构

## 任务

修改 `cache.kv` 的 TTL 策略，将 `fn set(key: CacheKey, value: String, ttl: CacheTtl)` 中的固定 `CacheTtl` 参数替换为 per-key configurable 的 `CacheTtlPolicy` 类型，该类型支持两种模式：固定时长（`Fixed(CacheTtl)`）和无过期（`NoExpiry`）。更新 `cache.kv` 的公开接口，检查 `user.profile_service` 调用 `cache.kv` 的位置是否需要更新，并确认 `reads_clock` effect 传播是否有变化。

## 标准答案

### 1. `cache.kv`（主要改动）

#### 新增类型 `CacheTtlPolicy`

既有 `CacheKey` / `CacheTtl` 公开 newtype 及 `new_key` / `new_ttl`
构造函数保持不变；本任务只在 TTL 参数外层新增策略类型。

`spec.interface` 新增：

```
type CacheTtlPolicy
  // TTL 策略枚举：
  //   Fixed(CacheTtl)  — 使用固定时长 TTL
  //   NoExpiry         — 永不过期（不读取时钟）
```

implementation rust 新增：

```rust
pub enum CacheTtlPolicy {
    Fixed(CacheTtl),
    NoExpiry,
}
```

#### 更新 `fn set` 签名

`spec.interface`：

```
fn set(key: CacheKey, value: String, policy: CacheTtlPolicy) -> ()
  effects [reads_clock]
  // 当 policy = Fixed(_) 时读取 time.clock.now() 记录写入时刻
  // 当 policy = NoExpiry 时不读取时钟（但模块级 effects 保守声明仍保留 reads_clock）
```

implementation rust：

```rust
pub fn set(_key: CacheKey, _value: String, _policy: CacheTtlPolicy) {
    todo!("cache.kv::set: real implementation pending")
}
```

#### effects 声明不变

`cache.kv` 的模块级 `effects [reads_clock]` 保持不变。即使 `NoExpiry` 路径不读时钟，`Fixed(CacheTtl)` 路径仍然需要，模块级声明是保守的。

---

### 2. `user.profile_service`（调用侧，必须更新）

`update_profile` 中的 `kv::set(key, String::new(), ttl)` 调用需更新：

- 旧：`let ttl = CacheTtl(300); kv::set(key, String::new(), ttl);`
- 新：`kv::set(key, String::new(), CacheTtlPolicy::Fixed(CacheTtl(300)));`
- 同时需要在 `use` 语句中引入 `CacheTtlPolicy`

`user.profile_service` 的 effects 声明**不变**（reads_clock 已声明）。

---

### 3. effects 传播不变

`reads_clock` 的传播路径不变：`time.clock → cache.kv → user.profile_service`（和其他 import cache.kv 的模块）。添加 `CacheTtlPolicy` 类型不引入新 effects，也不移除现有 effects。

---

### 4. 其他调用 `cache.kv.set()` 的模块（必须更新）

以下模块也 import `cache.kv`，若它们有调用 `kv::set()`，同样需要更新：

| 模块 | 对 cache.kv 的使用 |
|------|-------------------|
| `session.service` | 调用 kv::get / kv::set（cache session token）|
| `rate.limiter` | 调用 kv::get / kv::set / kv::delete（rate limit 计数）|

本实验使用全量公平素材，任务要求明确检查所有 `cache.kv.set()` 调用方。因此 `session.service` 和 `rate.limiter` 中的 `kv::set()` 调用也属于满分必须更新项。

---

### 完整改动清单

```
cache/kv.nico            spec.interface：新增 CacheTtlPolicy 类型，更新 set() 签名
                         implementation rust：新增 CacheTtlPolicy enum，更新 set() 参数
user/profile_service.nico implementation rust：更新 kv::set() 调用，引入 CacheTtlPolicy
session/service.nico      implementation rust：更新 kv::set() 调用，引入 CacheTtlPolicy
rate/limiter.nico         implementation rust：更新 kv::set() 调用，引入 CacheTtlPolicy
```

## 评分 Rubric

### task_success（0 / 0.5 / 1）

**1.0（满分）** 需同时满足：

- 正确在 `cache.kv` 中新增 `CacheTtlPolicy` 类型并更新 `set()` 签名
- 正确更新 `user.profile_service` 中的 `kv::set()` 调用（传入 `CacheTtlPolicy::Fixed(...)`）
- 正确更新 `session.service` 和 `rate.limiter` 中的所有 `kv::set()` 调用
- 正确判断 `reads_clock` effect 传播不变
- 未错误修改 `get()` 或 `delete()` 签名（这两个函数不使用 TTL）

**0.5（部分完成）** 适用于：

- 正确更新了 `cache.kv` 接口，但遗漏一个或多个调用侧
- 更新了 `user.profile_service`，但 `CacheTtlPolicy` 类型设计有缺陷（如缺少 `Fixed` variant）
- 错误修改了 `reads_clock` effects 声明

**0.0**：

- 未修改 `cache.kv` 的 `set()` 签名
- 完全错误地理解任务（如把 `get()` 的返回类型改了）

### compile_rate

- `cargo build` 通过（exit 0）
- 若任一 `kv::set()` 调用未更新：编译报类型不匹配错误

### boundary_violation

- `cache.kv` 不应引入新的 import（不依赖 metrics.recorder、user.types 等）
- 调用侧的 import 集合变化仅为新增 `CacheTtlPolicy` 的 use（来自 cache::kv），不引入新模块依赖

## 实验注意事项

**条件 A（raw Rust）：** LLM 需要阅读 `cache/kv.rs`（含 `CacheKey`、`CacheTtl` 类型和 `set` 函数），以及 `user/profile_service.rs` 中对 `kv::set()` 的调用。骨架实现中无参数类型的注释，推断 TTL 语义需要阅读 intent。

**条件 C（Semantic DB）：** 可从 `trusted.types WHERE module = 'cache.kv'` 查看现有类型，从 `trusted.functions WHERE module = 'cache.kv'` 查看 `set()` 的当前签名。从 `trusted.call_graph WHERE callee_module = 'cache.kv' AND callee_fn = 'set'` 可找到所有调用 `kv::set()` 的模块（包括 user.profile_service、session.service、rate.limiter）。

**条件 D（注解 Rust）：** `@nico-fn` 注解包含函数签名，可快速定位 `set()` 的参数类型；`@nico-module-effects` 提供 effects 声明参考。

**已知 LLM 行为风险：**

- 遗漏 session.service 和 rate.limiter 中的 `kv::set()` 调用
- 错误地从 `set()` 签名移除 `effects [reads_clock]`（实际上 Fixed 路径仍需读钟）
- 将 `CacheTtlPolicy` 设计为新 module 而不是 cache.kv 的 internal type（过度分层）
