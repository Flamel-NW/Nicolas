# E1 Golden Reference — 添加 last_login_at 字段

## 任务

不修改任何模块的外部可见行为。在 `user.types` 的 `UserProfile` 中添加字段 `last_login_at: Timestamp`（`Timestamp` 类型来自 `time.clock`），并在所有依赖 `UserProfile` 的模块中做必要更新：① `user.store` 的持久化接口更新为读写新字段；② 确认 `audit.log` 的 `AuditEvent` shape 是否需要更新；③ 不引入新的禁止依赖方向（`user.types` 不得引用 `user.store`、`user.profile_service` 等上层模块）。

## 标准答案

### 架构决策点（必须明确说明）

在 `user.types` 中使用 `Timestamp` 类型需要 `import time.clock`。这会引入两个连锁效果：

1. **`user.types` 需声明 `effects [reads_clock]`**（因为 nicolas check 要求：若模块 import 了有 effects 的模块，其自身 effects 必须包含被导入模块的所有 effects）。
2. **`reads_clock` 随即传播到所有 import `user.types` 的模块**：`user.store`、`user.profile_service`、`user.admin_service`、`audit.log`、`session.types`。

这违反 `user.types` 当前 intent（"所有类型均为纯值类型：无 IO、无时钟、无持久化副作用"）。

合理的替代方案是 `last_login_at: u64`（raw 秒级时间戳），避免引入 `time.clock` 依赖，保持 `user.types` 为纯值模块。

**对于评分，两种路径均可得满分，前提是 LLM 明确说明了架构影响并做出一致的选择。**

---

### 路径 A：使用 `Timestamp` 类型（接受 effects 传播）

#### 1. `user.types`（主要改动）

- `UserProfile` struct 新增字段：`last_login_at: Timestamp`
- `spec.interface` 注释更新：`type UserProfile // { id: UserId, email: EmailAddress, status: UserStatus, last_login_at: Timestamp }`
- `fn new_profile` 签名更新：新增参数 `last_login_at: Timestamp`
- `spec` 新增：`imports [time.clock]`
- `spec` 新增：`effects [reads_clock]`（因 import time.clock 传播）
- implementation rust 中 `UserProfile` struct 新增 `pub last_login_at: crate::time::clock::Timestamp` 字段
- `new_profile` 函数新增参数并填充字段

#### 2. `user.store`（持久化接口更新）

- `spec.effects` 新增 `reads_clock`（因 import user.types，而 user.types 现在有 reads_clock）
- `load_profile` / `save_profile` / `mark_deactivated` 函数签名本身不变（签名不直接包含 Timestamp）
- 函数级 effects 可根据是否实际调用读钟操作更新（v0 skeleton 中可保持不变）
- implementation rust：`UserProfile` struct 变更后，骨架函数无需修改（仅影响真实实现）

#### 3. `user.profile_service`（调用侧）

- `spec.effects` 新增 `reads_clock`（已有，不变）
- `checks.examples` 中对 `new_profile` 的调用需补传 `last_login_at` 参数
- implementation rust：目前不直接调用 `new_profile`，无需修改 Rust 代码

#### 4. `user.admin_service`（调用侧）

- `spec.effects` 新增 `reads_clock`（当前无此 effect，需补充）
- `list_users()` 返回 `Vec<UserProfile>`，结构体字段增加不影响函数签名
- implementation rust：不直接构造 `UserProfile`，无需修改

#### 5. `audit.log`（不应修改）

- `AuditEvent` 仅含 `actor`、`action`、`subject_id: UserId`，**无需也不应该**添加 `last_login_at`
- audit.log 的 intent 明确："只接收不包含 secrets 和不必要 sensitive fields 的 event shapes"
- `last_login_at` 是 profile 数据字段，不属于 audit event 的安全记录范畴
- `spec.effects` 因 import user.types 会获得 `reads_clock`（传播，需声明）

---

### 路径 B：使用 `u64` 类型（避免 effects 传播）

- `UserProfile` struct 字段：`last_login_at: u64`（秒级 Unix 时间戳）
- `user.types` 的 `imports` 和 `effects` **均不变**（无需 import time.clock）
- `new_profile` 签名：新增 `last_login_at: u64` 参数
- 所有下游模块的 effects 声明**均不变**
- 调用方在调用 `new_profile` 前需自行调用 `time.clock::now()` 并转换为 u64

---

### 不应出现的错误改动

- 向 `AuditEvent` 添加 `last_login_at` 字段（违反 audit.log intent）
- `user.types` import `user.store` 或 `user.profile_service`（会创建循环依赖）
- 在 `user.types` 中直接调用 `time.clock::now()`（user.types 不应主动读取时钟；传入 Timestamp 是调用方的责任）

## 评分 Rubric

### task_success（0 / 0.5 / 1）

**1.0（满分）** 需同时满足：

- 正确更新 `user.types`（UserProfile 添加字段、new_profile 新增参数）
- 正确标识 `user.store` 的持久化接口需要处理新字段
- 正确判断 `audit.log` 的 `AuditEvent` **不需要**添加 `last_login_at`，并给出理由（intent 约束）
- 对 `reads_clock` 传播问题有明确立场：要么接受传播并列出受影响模块，要么选择 `u64` 方案并说明理由
- 未引入禁止依赖方向（user.types 不依赖上层模块）

**0.5（部分完成）** 适用于：

- 正确更新了 user.types 和 user.store，但对 audit.log 做了错误的修改（添加了 last_login_at 字段）
- 完成了主要改动，但遗漏了 effects 传播分析
- 选择了 `u64` 方案但未解释与原始 Timestamp 要求的取舍

**0.0**：

- 未能添加字段到 UserProfile
- 错误地把 `last_login_at` 加入 `AuditEvent`
- 引入了循环依赖（user.types → user.store）

### boundary_violation

- 若 `user.types` 出现 `import user.store`、`import user.profile_service` 等上层依赖：标记为 `boundary_violation`

## 实验注意事项

**条件 A（raw Rust）：** LLM 需通过扫描所有 `.rs` 文件中 `use super::types::UserProfile` 或 `UserProfile` 结构体字面量来发现依赖图。骨架实现中没有 effects 注释，推断传播链依赖 LLM 手动分析 import 结构。

**条件 C（Semantic DB）：** LLM 可直接查询 `trusted.imports WHERE imported_module = 'user.types'` 获得全部依赖方（user.store、user.profile_service、user.admin_service、audit.log、session.types）。`trusted.effects` 表明 user.types 当前无 effects，`trusted.propagated_effects` 可显示 reads_clock 的传播路径。

**条件 D（注解 Rust）：** `@nico-imports` 和 `@nico-module-effects` 注解提供与条件 C 相似的结构信息，但依赖手动维护，存在遗漏风险。

**已知 LLM 行为风险：**

- 将 `last_login_at` 错误加入 `AuditEvent`（过度应用"同步所有相关模块"规则，忽视 intent 约束）
- 忽略 `reads_clock` 传播，只改动 user.types 和 user.store，漏掉其余 5 个受影响模块的 effects 声明
- 在条件 A 下漏报 `user.admin_service`（因其不在任务描述的模块列表中，但实际 uses UserProfile）
